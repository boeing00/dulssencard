# Handoff: 덜쎈카드 (DulSsenCard) — Android 앱 UI

## Overview

결제 SMS를 **기기 안에서** 분류해 (1) 사용자가 설정한 개인 구매 추적 한도와 (2) 카드별 월간 추적 목표의 진행 상황을 보여 주는 Android 앱. 이 번들은 PRD v4의 P0 범위 화면 전체(온보딩 권한 고지, 홈 대시보드, 거래 결과함, 거래 상세·보정, 카드 등록/편집, 설정·내 데이터)를 하이파이로 구현한 디자인 참조물이다.

핵심 제약(정책·개인정보):
- SMS 원문, 주민등록번호, 카드번호, CVC는 **저장·표시·전송 금지**. 거래 상세는 매칭 근거(키워드/신뢰도/파서 버전/fingerprint)만 노출한다.
- 모든 집계값은 "개인 추적값"이며 카드사 공식 실적이 아니라는 고지를 홈과 거래 상세에 표시한다.
- 홈 하단 광고 지면은 **비타게팅**이며 거래/SMS 파생 데이터를 광고 SDK에 전달하지 않는다.

## About the Design Files

`prototype/` 안의 파일은 **HTML로 만든 디자인 참조물(프로토타입)** 이다. 의도한 외관과 동작을 보여 주는 것이 목적이며, 그대로 제품에 복사해 쓸 코드가 아니다. 해야 할 일은 이 화면들을 **대상 코드베이스의 기존 환경에서 다시 구현**하는 것이다. 이 제품은 Android 네이티브(Kotlin + Jetpack Compose)가 자연스러운 선택이며(SMS BroadcastReceiver, Keystore 암호화, Play 권한 선언이 필수), 기존 코드베이스가 없다면 Compose + Material 3를 기준으로 구현하되 아래 토큰으로 테마를 덮어쓴다.

파일 열기: `prototype/DulSsenCard App.dc.html`를 브라우저에서 열면 동작한다(같은 폴더의 `support.js`, `android-frame.jsx` 필요). 왼쪽 패널의 버튼은 데모용 SMS 수신 시뮬레이터이며 **제품 UI가 아니다** — 구현 대상은 오른쪽 기기 화면 안쪽뿐이다. 기기 프레임(상태바·제스처 바)도 데모용 목업이므로 구현하지 않는다.

## Fidelity

**High-fidelity.** 색상·타이포·간격·상호작용이 최종안이다. 픽셀 단위로 재현하되, 폰트/색은 아래 토큰 값을 그대로 사용한다. 프레임 기준 해상도는 **412 × 892 dp**(Android 기본 폰 폭). px 값은 dp로 1:1 대응시킨다.

## Screens / Views

### 1. 온보딩 — 권한 고지 (`onboard`)

**목적:** SMS 자동 집계의 가치와 데이터 처리 방식을 고지하고, 동의한 경우에만 권한을 요청한다.

**레이아웃:** 세로 스크롤, 패딩 34/26/26. 위에서 아래로 — 스텝 라벨 → 제목 → 설명 → 고지 리스트 → (flex spacer) → 주요 버튼 → 텍스트 버튼.

- 스텝 라벨: `STEP 1 / 3 · 권한 고지`, Mono 600/10px, ls .22em, `accent`.
- 제목: "결제 문자를 / 카드 목표로 / 자동 정리할게요" (3줄 개행 고정).
- 설명: Sans 400/14.5px, lh 1.7, `text-2`. "기기 안에서만"은 600 강조.
- 고지 리스트 4행, 각 행 상하 13px + 1px `line` 구분(마지막 행은 선 없음). 앞 글리프는 ✓(첫 3행, `accent`) / !(마지막, `text-3`). 문안:
  1. SMS 원문과 주민등록번호는 저장·전송하지 않습니다
  2. 광고·마케팅·분석 목적으로 사용하지 않습니다
  3. Android 설정에서 언제든 권한을 해제할 수 있고, 해제하면 새 결제 자동 반영이 중단됩니다
  4. 집계값은 사용자가 설정한 규칙에 따른 개인 추적값이며 카드사 공식 실적이 아닙니다 (`#6B6455`)
- 버튼: `SMS 자동 집계 켜기`(주요) / `나중에 하기`(텍스트).

**동작:** 켜기 → `smsOn = true`, 홈 이동, 스낵바 "SMS 자동 집계를 켰습니다". 나중에 → `smsOn = false`, 홈 이동, 스낵바 "제한 모드로 시작합니다 — 수동 보정만 가능합니다". 제한 모드에서는 신규 SMS 자동 반영과 P1 재스캔이 불가하고 열람·수동 보정만 가능하다.

### 2. 홈 대시보드 (`home`)

**목적:** 결제 후 3초 안에 남은 한도와 카드별 남은 목표를 확인한다. 정보 우선순위는 **한도 → 카드별 남은 목표 → 확인 필요**.

**마스트헤드** (패딩 22/22/16, flex, 하단 정렬):
- 왼쪽: 계단형 바 그래픽(6×13 `line`, 6×22 `masthead-mid`, 6×32 `ink`, gap 3px, 라운드 1px, padding-bottom 6px) + `SMS → 추적` 카플라벨 + 34px 워드마크(덜쎈 + `accent` 카드).
- 오른쪽: `D-{남은일수}` 필(Mono 500/11px, 테두리 `line`, 라운드 999px, 패딩 6×10).

**한도 카드** (좌우 22px, 위 토큰의 브라운 표면):
- 헤더행: 라벨 `개인 구매 추적 한도`(Mono 500/10px, ls .18em, `brown-label`) + 우측 `한도 설정` 링크(Sans 400/11px, `#4A3A22`, 밑줄 `rgba(74,58,34,.4)`) → 설정 화면.
- 금액 블록(margin-top 14): 1행 사용액 Mono 500/28px `brown-ink` nowrap, 2행 `한도 {총액}` Mono 400/13px `brown-label` nowrap. **두 값은 반드시 각자 한 줄** (5,000,000원까지 잘리지 않아야 함).
- 진행 막대: 높이 10px, 트랙 `rgba(90,66,38,.20)` + `inset 0 1px 2px rgba(90,66,38,.28)`, 채움 `linear-gradient(180deg,#5A4426,#3A2B15)`, 라운드 1px, 0–100% 클램프.
- 하단행: `남은 금액 {금액}`(금액만 Mono 500 `brown-ink`) + 우측 `N% 사용`. 둘 다 nowrap.
- 카드 아래 9px: 고지문 Sans 400/11px `text-3` — "사용자 설정과 SMS 분류에 따른 추적값이며 카드사 공식 실적과 다를 수 있습니다."

**확인 필요 배너** (확인 필요 ≥1건일 때만): 좌우 22px, 테두리 1px `accent`, 배경 `accent-tint`, 라운드 3px, 패딩 14×16. 텍스트 "확인 필요 N건 — 합계에 반영되지 않음"(Sans 500/13.5px `accent-press`) + 우측 `→`. 탭 → 결과함(확인 필요 탭). hover 배경 `#F4DFD3`.

**카드 섹션**: 헤더행(패딩 26/22/10) = 섹션 라벨 `카드별 남은 목표` + 우측 정렬 토글 링크(`남은 금액순` ↔ `이름순`, 탭하면 전환). 상단 1px `line`.

**카드 행** (각 행 패딩 16/22/17, 하단 1px `line`, hover 배경 `paper-2`, 커서 포인터):
1. 1행: 별명(Sans 500/15.5px) + 우측 남은 금액(Mono 500/17px). 목표 달성 시 텍스트 `목표 달성`, 색 `green`.
2. 2행(margin-top 7): `{누적} / {목표}`(Mono 400/12px `#6B6455`) + 우측 상태 배지 `TRACKING`(`text-3`) 또는 `COMPLETE`(`green`).
3. 진행 막대(margin-top 10): 높이 5px, 트랙 `line`, 채움 `ink`(달성 시 `green`), 0–100% 클램프.
4. 4행(margin-top 8): `매월 N일 시작 · 남은 N일`(Sans 400/11px `text-3`).
- **완료된 카드는 리스트 하단으로 정렬되고 opacity 0.5로 저대비 처리.**
- 행 탭 → 결과함(전체 탭).

**광고 지면** (카드 리스트 바로 아래, 패딩 18/22/4, 가운데 정렬): **320×50 고정**, 배경 `paper-2`, 테두리 1px `line`, 라운드 2px, 좌우 패딩 10, gap 12. 왼쪽 34×34 썸네일 자리(`line` 채움, 라운드 2px), 오른쪽 2줄 텍스트(제목 Sans 500/12px `text-body`, 부제 Sans 400/10.5px `text-2`, 둘 다 ellipsis). 우상단 `AD` 배지(Mono 600/8.5px, ls .1em, 배경 `#4A4437`, 텍스트 `paper`, 패딩 3×4, 라운드 `0 0 0 2px`). 형식 배너 320×50, 표기는 AD 배지만, 광고 제거 옵션 없음. **구현 시 광고 SDK에 거래·SMS 파생 데이터를 전달하지 말 것.**

**푸터 노트** (패딩 18/22/28, Sans 400/11px `text-3`): "완료된 카드는 하단으로 이동하며 낮은 대비로 표시됩니다. 카드사 공식 인정 여부는 앱이 판정하지 않습니다."

### 3. 거래 결과함 (`inbox`)

**목적:** 확인 필요 거래를 처리하고 전체 거래를 열람한다.

- 헤더: 섹션 라벨 `거래 결과함` + h2(탭에 따라 `확인 필요` / `모든 거래` / `제외된 거래`).
- 탭 칩 3개: `확인 필요 {n}` / `전체 {n}` / `제외됨`(패딩 6/22/14, gap 6).
- 거래 행(패딩 15/22, 하단 1px `line`, gap 14, hover `paper-2`): 왼쪽 3px 상태 컬러 바(행 높이 전체, 라운드 2px) + 본문.
  - 1행: 가맹점(Sans 500/14.5px) + 우측 금액(Mono 500/15px). 취소 거래는 앞에 `−` 기호와 `green`, 자동 반영이 아닌 상태는 금액 색 `text-3`.
  - 2행(margin-top 6): `{카드명 또는 미분류} · {시각}`(Sans 400/11.5px `#6B6455`) + 우측 상태 라벨(Mono 400/10.5px, uppercase, 상태 색).
  - 사유 박스(확인 필요/제외됨에 사유가 있을 때만, margin-top 7): 배경 `accent-tint`, 텍스트 `accent-press` Sans 400/11.5px, 라운드 2px, 패딩 7×9.
- 상태별 색: 자동 반영 `ink` / 확인 필요 `accent` / 제외됨 `text-3` / 취소 반영 `green`.
- 빈 상태(패딩 56/30, 가운데): "해당하는 거래가 없습니다" + "새 결제 SMS가 도착하면 여기에 정리됩니다."
- 행 탭 → 거래 상세.

### 4. 거래 상세·보정 (`detail`)

**목적:** 오인식·취소·실적 제외를 **3동작 이내**로 처리한다.

- 뒤로: `← 결과함`(Mono 500/12px `#6B6455`, 패딩 18/22/0).
- 헤더 블록(패딩 18/22/20, 하단 1px `line`): 상태 라벨(Mono 400/10.5px, ls .14em, uppercase, 상태 색) → 금액 Mono 500/36px(취소는 `−` + `green`) → 가맹점 Sans 500/15px → 시각 Mono 400/12.5px `#6B6455` (`{시각} · 승인|취소`).
- **카드 섹션**: 섹션 라벨 `카드` + 등록된 카드 전체를 칩으로 나열(가로 wrap, gap 7). 칩 탭 = 해당 카드로 이동. 확인 필요 상태였다면 이동 시 `auto`로 승격. 스낵바 "{카드명}(으)로 이동했습니다" + 되돌리기.
- **토글 2행**(각 패딩 16/22, 1px `line` 구분): `목표 추적 포함`(설명 "카드 월간 추적 목표에 합산") / `구매 추적 한도 포함`(설명 "개인 구매 추적 한도에 합산"). **두 값은 완전히 독립**이며 거래 단위로 저장한다. 변경 시 스낵바 + 되돌리기.
- **매칭 근거**(좌우 22px, 테두리 1px `line`, 배경 `paper-2`, 라운드 3px): key/value 4행 — 매칭 키워드 / 파싱 신뢰도(소수 2자리) / 파서 버전(`v3.2 · KR-SMS`) / fingerprint(축약 표기). 마지막에 "SMS 본문은 저장·표시하지 않습니다."
- **변경 기록**: `{시각} {설명}` 목록(9px 상하 패딩, 1px `line`). 없으면 "아직 보정 기록이 없습니다."
- 하단 버튼 2개(패딩 22/22/30, gap 8): 주요 = `집계 확정`(제외됨 상태면 `제외 복원`) / 보조 = `실적 제외`. 두 동작 모두 변경 기록을 남기고 스낵바 + 되돌리기를 제공한다.

### 5. 카드 설정 목록 (`cards`)

- 헤더: 섹션 라벨 `카드 설정` + h2 `{N}장 추적 중` + 우측 `+ 카드 추가` 버튼(테두리 1px `ink`, 라운드 2px, 패딩 10×12, hover 반전).
- 카드 행(패딩 16/22, 하단 1px `line`, hover `paper-2`): 별명(Sans 500/15px) + 우측 `목표 {금액}`(Mono 400/11.5px `#6B6455`); 2행 `인식 키워드 {키워드} · 매월 N일 시작`(Sans 400/11.5px `text-3`).
- 푸터 노트: "동일 키워드를 여러 카드에 저장하면 해당 거래는 자동 반영하지 않고 확인 결과함으로 이동합니다."
- 행 탭 → 편집 화면(값 프리필).

### 6. 카드 등록·편집 (`edit`)

- 뒤로 `← 카드`, h2 `카드 추가` / `카드 편집`.
- 필드(세로 gap 18, 패딩 20/22/0). 라벨은 Mono 600/10px, ls .16em, uppercase, `text-3`:
  1. **별명 · 필수** — 밑줄 1px `ink`, 입력 Sans 400/17px, placeholder `예: 신한 딥드림`.
  2. **월간 추적 목표 · 필수** — 밑줄 1px `ink`, 입력 Mono 500/17px + 접미 `원`(Sans 400/14px). 높이 36px 라인으로 숫자와 `원`의 baseline을 맞춘다. **입력 중 천 단위 쉼표 자동 삽입**(숫자만 남기고 `ko-KR` 로케일 포맷; 빈 값이면 공백). placeholder `300,000`.
  3. **인식 키워드 · 1개 이상** — 밑줄 1px `ink`, Sans 400/15px, placeholder `신한, 신한카드`, 도움말 "쉼표로 구분. 발신 SMS에서 이 키워드를 찾습니다."
  4. **제외 키워드 · 선택** — 밑줄 1px `line`, placeholder `해외, 할부`.
  5. **주기 시작일 · 1~28** — 38×38 정사각 칩 `1,5,10,15,20,25,28`(gap 6, wrap). 실제 구현은 1–28 전체를 제공한다.
  6. 기본값 토글 2개: `기본값: 목표 추적 포함`, `기본값: 구매 추적 한도 포함`. **카드 기본값은 새 거래에만 적용**되고 기존 거래를 바꾸지 않는다.
- 저장 버튼: `카드 저장` / `변경 저장`(주요 버튼, 하단 여백 30).
- **검증:** 별명·목표·인식 키워드가 비면 저장하지 않고 스낵바 "별명·목표·인식 키워드는 필수입니다". 목표는 숫자만 추출해 정수로 파싱, 0이면 실패.
- 카드별 주기는 매월 `시작일 00:00` ~ 다음 달 `시작일 직전`.

### 7. 설정 · 내 데이터 (`settings`)

- 헤더: 섹션 라벨 `설정` + h2 `한도와 내 데이터`.
- **한도 박스**(좌우 22px, 테두리 1px `line`, 라운드 3px, 패딩 16): 라벨 `개인 구매 추적 한도` + 금액 입력(밑줄 1px `ink`, Mono 500/22px, 높이 38px 라인으로 `원`과 정렬) + 도움말 "기본값 1,000,000원은 제안값일 뿐이며 언제든 바꿀 수 있습니다. 카드 주기와 독립적으로 계산됩니다."
- 리스트(각 패딩 16/22, 1px `line`):
  1. **SMS 자동 집계** + 토글. 부제 = ON "새 결제 SMS를 기기 안에서 자동 반영합니다" / OFF "제한 모드 — 열람·수동 보정만 가능합니다". OFF 전환 시 스낵바 "권한 해제 — 새 SMS 접근을 중단했습니다" 그리고 **즉시 신규 SMS 접근 중단**.
  2. **암호화 내보내기** `P1` 배지 — "비밀번호를 잃어버리면 복구할 수 없습니다."
  3. **최근 14일 내역 불러오기** `P1` 배지 — "누를 때만 읽기 권한을 별도로 설명·요청합니다."
  4. **로컬 데이터 전체 삭제**(텍스트 `accent`, hover 배경 `accent-tint`) — "카드·거래·보정 기록이 기기에서 지워집니다." 실제 구현에서는 **확인 다이얼로그를 반드시 추가**한다(프로토타입은 즉시 삭제 + 되돌리기 스낵바).
- `P1` 배지: Mono 600/9.5px, ls .1em, 테두리·텍스트 `accent`, 라운드 2px, 패딩 3×5, 좌측 마진 8.
- 푸터: "로컬 DB는 Android Keystore 기반 키로 암호화됩니다. SMS 원문·주민등록번호·카드번호·CVC는 저장하지 않습니다."

## Interactions & Behavior

- **내비게이션:** 하단 4탭 + 화면 내 진입(배너 → 결과함, 한도 설정 → 설정, 카드 행 → 결과함, 카드 목록 → 편집, 거래 행 → 상세). 상세/편집의 뒤로는 진입 지점(`backTo`)으로 복귀한다.
- **화면 전환 시 스낵바를 즉시 닫는다.**
- **되돌리기:** 보정성 변경(카드 이동, 목표/한도 토글, 집계 확정, 제외, 복원, 데이터 삭제)은 변경 직전 스냅샷(cards/txs/limitAmount)을 저장하고 스낵바에 `되돌리기`를 노출한다. **마지막 1건만** 되돌릴 수 있고 4.2초 후 만료된다. 정보성 스낵바(카드 저장, 권한 토글, SMS 수신 알림)는 되돌리기를 제공하지 않는다.
- **변경 기록:** 모든 보정은 `{시각, 설명}`을 거래 로그 맨 앞에 추가한다. 실제 구현은 PRD 8절대로 원값·변경값·시간·사유를 남긴다.
- **집계 재계산:** 어떤 보정이든 즉시 홈 한도·카드 합계·확인 필요 배지에 반영된다(파생 계산, 별도 캐시 없음).
- **애니메이션:** 진행 막대 width 0.45s, 토글 노브 0.2s. 그 외 전환 없음.
- hover는 데스크톱 프리뷰용 표현이므로 Android에서는 **press/ripple 상태로 대체**한다. 터치 타깃은 최소 44dp 유지(리스트 행·토글·칩 모두 충족).

### 집계 규칙 (구현 필수)

- 카드 누적 = `그 카드의 status == auto && countsTowardTarget` 거래 합. 취소(`dir == cancel`)는 **차감**.
- 한도 사용액 = `status == auto && countsTowardPurchaseLimit` 거래 합(카드 무관), 취소는 차감.
- `pending`(확인 필요)과 `excluded`(제외)는 **어떤 합계에도 반영하지 않는다.**
- 진행률은 0–100%로 클램프한다. 남은 금액이 0 이하면 `목표 달성` + `COMPLETE` + 하단 정렬 + opacity 0.5.
- 자동 반영 조건: 단일 카드 키워드 일치 + 필수 필드(금액·상태·시각·발신 식별자) 추출 + 신뢰도 기준 충족. 다중 매칭·파싱 실패·신뢰도 미달·미연결 취소는 `pending`.
- 부분 취소는 원 승인 거래의 남은 금액을 초과 차감하지 않는다. 원 거래를 못 찾으면 `pending`.
- 해외 승인, 할부, 통화 미상, 금액 0원, 시각 미상은 자동 반영하지 않는다.
- 중복 판별은 `messageFingerprint` **전체 일치**만. 금액+근접 시각만으로 삭제하지 않는다.
- 기본 시간대 `Asia/Seoul`. 카드 주기와 한도 주기는 독립 계산.

## State Management

프로토타입의 단일 상태 트리(실제 구현에서는 ViewModel + 암호화 Room DB로 분리):

```
screen: 'onboard'|'home'|'inbox'|'detail'|'cards'|'edit'|'settings'
backTo: 복귀 화면
tab: 'pending'|'all'|'excluded'      // 결과함 필터
sort: 'left'|'name'                  // 홈 카드 정렬 (기본 남은 금액순)
sel: 선택된 거래 id
editId: 편집 중 카드 id (null이면 신규)
smsOn: boolean                       // 권한/제한 모드
limitAmount: number, limitInput: string
form: { nickname, target, keywords, exclude, startDay, dTarget, dLimit }
toast: string|null, undoSnap: 스냅샷|null
cards[], txs[]
```

엔티티(PRD 8절 그대로):

```
Card    id, nickname, trackingTarget, cycleStartDay, matchKeywords[],
        excludeKeywords[], defaultCountsTowardTarget,
        defaultCountsTowardPurchaseLimit, active
PurchaseLimit  id, name, amount, cycleStartDay, active
Transaction    id, cardId?, occurredAt, amount, currency,
        direction(approval|cancel|manual), status(auto|pending|excluded),
        source(SMS|manual), merchant?, countsTowardTarget,
        countsTowardPurchaseLimit, parserVersion, confidence,
        messageFingerprint, relatedTransactionId?
Adjustment     id, transactionId?, changeType, beforeState, afterState, reason?, createdAt
CycleSnapshot  cycleKey, cardTotals, purchaseLimitTotal, closedAt
```

데이터 요구사항: 네트워크 호출 없음. 신규 SMS는 BroadcastReceiver → 기기 내 파서 → fingerprint 중복 검사 → 분류. 로컬 DB는 Android Keystore 기반 키로 암호화. 진단 로그에 거래 데이터·매칭 키워드를 남기지 않는다.

프로토타입의 시드 데이터(카드 3장 / 거래 9건 — 자동 반영, 취소 반영, 확인 필요 2건, 제외 1건)는 화면 상태를 보여 주기 위한 샘플이며 그대로 구현할 필요는 없다. 단, **각 상태가 최소 1건씩 보이는 조합**은 QA 시나리오로 유용하다.

## 구현 시 열린 결정사항 (PRD 13절)

1. P0에 실제로 필요한 Android SMS 권한 조합과 Android 버전별 동작.
2. 개인 구매 추적 한도의 복수 한도 지원 여부(현재 UI는 단일 한도).
3. 카드사별 제외 규칙을 P1에 제공할지 여부.
4. P1 암호화 백업의 비밀번호 UX와 복구 책임 고지.
5. 정책 심사 거절 시 수동·제한 모드 배포 유지 여부(제한 모드 UI는 이미 설계에 포함).
