# 결제 알림 회귀 코퍼스

이 앱의 품질은 화면보다 **파서 정확도와 중복 방지**에서 나온다. 카드사는 예고 없이 문구를
바꾸고, 그때마다 여기에 실제 문구를 한 건씩 더해 고정한다. 파일 하나가 알림 한 건이다.
`CorpusTest` 가 폴더의 모든 파일을 읽어 파서에 넣고 기대값과 비교한다.

## 반드시 익명화한다 — 저장소는 공개다

실제 알림에는 이름·카드 뒷자리·가맹점·누적액이 들어 있다. **넣기 전에 전부 바꾼다.**
2026-09-12 에 실측 문구를 테스트에 넣으면서 실명·가족카드 뒷자리·실제 가맹점이 공개 저장소에
올라간 적이 있다. 그래서 `AnonymizationGuardTest` 가 저장소 전체를 훑어 막는다 — 허용 목록에 없는
가린 이름·카드 뒷자리·전화번호·주민번호가 보이면 테스트가 실패한다.

| 원문에 있는 것 | 바꿀 값 | 이유 |
|---|---|---|
| 가린 이름 `○*○`, `○*○님` | `홍*동` | 가린 형태도 가족 구성·지역을 좁힌다 |
| **실명** (광고 배너 `OOO님 맞춤 카드` 등) | `홍길동` | 검사로 못 잡는다. **눈으로 확인** |
| 카드 뒷자리 `(NNNN)`, `삼성가족NNNN승인` | `1234` `4321` `8821` `2468` `5678` 중 하나 | |
| 가맹점 | 같은 **글자 수·공백·괄호·`(주)`** 를 가진 가짜 상호 | 파서가 깨지는 건 이 성질 때문이다 |
| 누적액 `누적N,NNN,NNN원` | 가짜 값. 여러 건이면 **앞뒤 관계(누적 = 이전 + 결제액)를 유지** | 월 사용 규모가 드러난다 |
| 결제 금액·시각 | 그대로 둬도 된다 | 위를 다 바꾸면 누구의 결제인지 알 수 없다 |

**바꾸지 말 것**: OCR 오인식 글자(`12,820l`, `5,6002!`), 전각 공백, 줄바꿈 위치, 하단 마케팅 문구.
이것들이 파서를 깨뜨린 원인이라 바꾸면 회귀 테스트가 아무것도 지키지 못한다.

## 파일 형식

```
source: KAKAO                      SMS · PUSH · KAKAO · IMAGE
sender: com.kakao.talk             알림을 띄운 패키지
title: 우리카드                    알림 제목(없으면 줄을 뺀다)
receivedAt: 2026-09-07T21:19       Asia/Seoul
expect.reject: false               결제가 아니라서 버려야 하면 true (아래 expect.* 생략)
expect.issuer: WOORI
expect.direction: APPROVAL         APPROVAL · CANCEL
expect.amount: 16000
expect.occurredAt: 2026-09-07T21:18
expect.merchant: 푸른들컨트리클럽　주식
expect.cardSuffix: 4321
note: 함정이 무엇인지 한 줄
---
(알림 본문. 이 줄 아래 전부가 그대로 본문이다)
```

`expect.*` 는 적은 것만 검사한다. 모르는 값은 적지 않는다 — 틀린 기대값은 없는 기대값보다 나쁘다.
파일 이름은 `카드사-경로-특징.txt` 로 짓는다(예: `samsung-kakao-family-suffix.txt`).
