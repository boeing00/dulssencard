# 제품 요구사항 문서 (PRD) v4 — 덜쎈카드

> 목적: Google Play 출시와 실제 구현을 전제로, 결제 SMS 자동 집계·사용자 보정·개인정보 최소화를 일관된 요구사항으로 확정한다.

## 1. 제품 정의

**덜쎈카드는 결제 SMS를 기기 안에서 분류하여, 사용자가 설정한 카드별 월간 추적 목표와 개인 구매 추적 한도의 진행 상황을 보여 주는 Android 앱이다.**

자동 집계가 없으면 사용자가 결제마다 직접 기록해야 하므로, ‘가볍고 즉시 갱신되는 실적 관리’라는 핵심 가치를 제공할 수 없다. 다만 이 앱의 집계는 카드사가 확정하는 공식 실적 또는 법적·금융기관의 한도 조회가 아니라, 사용자가 설정한 규칙에 따른 **개인용 추적값**이다.

### 제품 원칙

- 자동화는 명확한 거래만 처리하고, 불확실한 거래는 사용자 확인을 우선한다.
- SMS 원문과 주민등록번호는 저장·전송·요청하지 않는다.
- 모든 집계값은 사용자가 변경·제외·되돌릴 수 있다.
- 자동 SMS 집계는 핵심 기능이며, 권한이 없을 때는 제한 모드로 작동한다.

## 2. 목표 사용자와 핵심 작업

| 사용자 | 하려는 일 | 완료 기준 |
|---|---|---|
| 카드 추적 사용자 | 이번 달 카드별 남은 목표 확인 | 홈에서 카드별 누적·남은 금액 확인 |
| 구매 한도 추적 사용자 | 개인 월 구매 추적 한도 확인 | 한도 게이지와 남은 금액 확인 |
| 신규 사용자 | 결제 SMS를 분류할 첫 카드 설정 | 카드 별명·목표·키워드 저장 |
| 예외 처리 사용자 | 오인식·취소·실적 제외 처리 | 거래를 제외·이동·보정하고 즉시 재집계 |

## 3. 성공 기준

1. 사용자는 결제 뒤 3초 안에 남은 카드 추적 목표와 개인 구매 추적 한도를 확인한다.
2. 명확히 일치하는 신규 결제 SMS는 수신 뒤 5초 안에 집계된다.
3. 다중 매칭·파싱 실패·원 거래가 없는 취소는 자동 집계하지 않는다.
4. 사용자는 세 번 이내 동작으로 거래의 추적 포함 여부·카드·한도 포함 여부를 수정한다.

## 4. 출시 범위

### P0 — 공개 출시 필수

- 신규 결제 SMS 수신, 기기 내 파싱, 중복 판별
- 카드 등록: 별명, 월간 추적 목표, 인식·제외 키워드, 카드별 집계 기준일
- 홈: 카드별 목표, 개인 구매 추적 한도, 확인 필요 거래
- 거래 결과함과 거래별 보정: 카드 변경, 추적 포함/제외, 한도 포함/제외, 수동 증감
- 월별 또는 카드별 주기 아카이브·현재 주기 계산
- 로컬 암호화·전체 데이터 삭제·권한 해제 처리
- Play 권한 고지, 개인정보 처리방침, Permissions Declaration 자료

### P1 — P0 정확도 검증 뒤

- 사용자가 실행한 최근 14일 SMS 재스캔
- 암호화된 내보내기·가져오기
- Google Drive 앱 전용 폴더 백업
- 카드사별 파서 템플릿과 키워드 추천

### 비목표

- 카드사 공식 실적·한도 조회, 마이데이터, 결제·송금, 카드 추천·발급
- 광고, SMS 기반 분석·프로파일링, 제3자 데이터 제공
- 알림 접근 권한을 통한 앱 푸시 파싱
- 주민등록번호, 금융기관 로그인 정보, 카드 번호·CVC 수집

## 5. 권한 전략과 출시 게이트

### P0 권한 경계

P0는 **앞으로 도착하는 결제 SMS 자동 반영**만 제공한다. 따라서 최근 SMS 읽기, 과거 내역 재스캔, 첫 카드 후보 제안은 P1로 이동한다. 이 구분으로 P0의 SMS 접근 범위와 사용자 고지를 최소화한다.

- P0: 새 결제 SMS 수신에 필요한 권한만 선언한다.
- P1: 사용자가 `최근 14일 내역 불러오기`를 누른 경우에만 읽기 권한을 별도로 설명·요청하고 재스캔한다.
- 권한을 해제하면 즉시 신규 SMS 접근과 자동 집계를 중단한다.

### Google Play 출시 게이트

1. Permissions Declaration에 ‘SMS 기반 자금 관리’ 사용 사례, 요청 권한, 기기 내 처리 방식을 정확히 제출한다.
2. 앱 설명·스크린샷·온보딩에 SMS 자동 집계가 핵심 기능임을 일관되게 보여 준다.
3. 개인정보처리방침과 인앱 고지에 수집 항목·목적·미전송·권한 해제·데이터 삭제를 명시한다.
4. 심사용 절차에서 SMS 수신 → 추출 → 집계/확인 필요 분기 → 사용자 보정을 재현한다.
5. 출시 빌드의 네트워크 요청과 SDK를 점검해 SMS 및 파생 정보가 외부로 전송되지 않음을 검증한다.
6. 심사 거절 시 SMS 권한을 제거한 제한 배포 또는 수동 추적 제품으로 전환한다.

Google Play는 ‘SMS 기반 자금 관리(예: 예산 추적·관리)’를 예외 사용 사례 표에 열거하지만, 핵심 기능성·다른 방법 부재·권한 선언·검토 승인을 요구한다. [공식 정책](https://support.google.com/googleplay/android-developer/answer/10208820?hl=ko)

### 권한 고지 문구 초안

**결제 문자를 카드 목표로 자동 정리할게요**

덜쎈카드는 새로 도착하는 결제 SMS에서 카드사 키워드, 금액, 승인·취소 상태, 거래 시각을 기기 안에서만 추출해 개인 추적값을 계산합니다. SMS 내용과 추출 정보는 광고·마케팅·분석 목적으로 사용하거나 외부 서버로 전송하지 않습니다. 주민등록번호는 수집하지 않습니다. 권한은 언제든 Android 설정에서 해제할 수 있으며, 해제하면 새 결제의 자동 반영이 중단됩니다.

버튼: `SMS 자동 집계 켜기` / `나중에 하기`

## 6. 핵심 사용자 흐름

### 6.1 첫 사용

1. 자동 SMS 집계의 가치와 데이터 처리를 설명한다.
2. 사용자가 동의한 경우에만 P0 SMS 권한을 요청한다.
3. 사용자가 카드 별명, 월간 추적 목표, 인식 키워드를 저장한다.
4. 이후 새 결제 SMS만 자동 분류한다.

권한을 거부하면 제한 모드가 된다. 제한 모드에서는 저장된 내역 열람·수동 보정·카드 설정은 가능하지만, 신규 SMS 자동 반영과 P1 재스캔은 불가능하다.

### 6.2 자동 분류

1. 새 SMS를 수신한다.
2. 기기 내 파서가 발신 식별자·금액·상태·시각을 추출한다.
3. 최소 필드 fingerprint로 중복을 검사한다.
4. 카드 키워드가 한 개와 일치하고 파싱 신뢰도가 기준 이상이면 자동 반영한다.
5. 다중 매칭, 추출 실패, 신뢰도 미달, 미연결 취소는 확인 결과함에 저장한다.
6. 거래별 기본값에 따라 목표 추적·구매 추적 한도를 각각 집계한다.

### 6.3 사용자 보정

사용자는 거래 상세에서 다음을 바꿀 수 있다.

- 카드: 미분류 또는 잘못 매칭된 거래를 다른 카드로 이동
- 목표 추적: 포함 또는 제외
- 구매 추적 한도: 포함 또는 제외
- 금액: 추가 또는 차감
- 상태: 제외 후 복원

변경 시 원값, 변경값, 시간, 선택 사유를 기록하고 마지막 변경 1건은 되돌릴 수 있다.

## 7. 화면 요구사항

### 홈 대시보드

정보 우선순위: **개인 구매 추적 한도 → 카드별 남은 목표 → 확인 필요 거래**.

- 상단: `이번 주기 구매 추적액 / 사용자가 설정한 한도`, 남은 금액, 진행 막대
- 한도 설정 진입: 기본값 1,000,000원은 제안값일 뿐이며 사용자가 변경할 수 있다.
- 헤더: 기본 카드 집계 주기의 남은 일수, 정렬(기본: 남은 금액순)
- 카드 행: 별명, 누적/목표, 남은 금액, 추적 주기, 상태
- 완료 카드는 하단 이동·낮은 대비 처리, 숨기기 가능
- ‘확인 필요 N건’ 배너는 결과함으로 이동
- 모든 요약 옆에 ‘사용자 설정과 SMS 분류에 따른 추적값이며 카드사 공식 실적과 다를 수 있음’을 표시

### 카드 등록·편집

- 필수: 별명, 주기 목표, 인식 키워드 1개 이상
- 선택: 제외 키워드, 매월 주기 시작일(1~28일), 기본 목표 추적 포함, 기본 구매 추적 한도 포함
- 동일 키워드를 여러 카드에 저장하면 해당 거래는 자동 반영하지 않고 확인 결과함으로 간다고 고지한다.
- 카드별 주기는 매월 `시작일 00:00`부터 다음 달 `시작일 직전`까지다.
- 목표·한도에 대한 카드사 공식 인정 여부는 앱이 판정하지 않는다고 명확히 안내한다.

### 확인 결과함·거래 상세

| 상태 | 조건 | 합계 처리 |
|---|---|---|
| 자동 반영 | 단일 카드 일치·필수 항목 추출·신뢰도 기준 충족 | 거래별 포함 설정에 따라 합산 |
| 확인 필요 | 다중 매칭·파싱 실패·신뢰도 미달·미연결 취소 | 합산하지 않음 |
| 제외됨 | 제외 키워드 또는 사용자 제외 | 합산하지 않음, 복원 가능 |
| 취소 반영 | 원 승인 거래와 연결된 취소 | 해당 거래의 포함 설정에 따라 차감 |

상세 화면은 카드, 시각, 금액, 상태, 매칭 근거, 변경 기록만 보인다. SMS 전체 본문은 저장·표시하지 않는다.

## 8. 데이터 및 집계 규칙

```text
Card
  id, nickname, trackingTarget, cycleStartDay, matchKeywords[], excludeKeywords[],
  defaultCountsTowardTarget, defaultCountsTowardPurchaseLimit, active

PurchaseLimit
  id, name, amount, cycleStartDay, active

Transaction
  id, cardId?, occurredAt, amount, currency, direction(approval|cancel|manual),
  status(auto|pending|excluded), source(SMS|manual), merchant?,
  countsTowardTarget, countsTowardPurchaseLimit, parserVersion, confidence,
  messageFingerprint, relatedTransactionId?

Adjustment
  id, transactionId?, changeType, beforeState, afterState, reason?, createdAt

CycleSnapshot
  cycleKey, cardTotals, purchaseLimitTotal, closedAt
```

- `countsTowardTarget`와 `countsTowardPurchaseLimit`는 **거래 단위** 값이다. 카드 기본값은 새 거래에만 적용하며 사용자가 수정할 수 있다.
- `messageFingerprint`는 발신 식별자·정규화 시각·금액·상태를 일방향 해시한 값이다. SMS 원문을 저장하지 않는다.
- fingerprint 전체가 일치할 때만 중복으로 본다. 같은 금액·가까운 시간만으로 삭제하지 않는다.
- 부분 취소는 원 승인 거래의 남은 금액을 초과해 차감하지 않는다. 원 거래를 찾지 못하면 확인 필요 상태로 둔다.
- 해외 승인, 할부, 통화 미상, 금액 0원, 시각 미상은 자동 반영하지 않는다.
- 카드 집계 주기와 구매 추적 한도 주기는 독립적으로 계산한다. 기본 시간대는 `Asia/Seoul`이며 기기 설정 변경 시 기존 거래 시각은 보존한다.

## 9. 파서와 정확도 관리

### 파서 원칙

- 카드사·발신 형식·파서 버전을 거래에 기록해 형식 변경을 추적한다.
- 추출 필수값은 금액, 상태, 시각, 발신 식별자다. 하나라도 없으면 자동 반영하지 않는다.
- 카드사별 정규식은 버전 관리하고, 변경 전 회귀 테스트를 통과해야 한다.

### 테스트 코퍼스

내부 테스트용으로 비식별·합성 SMS 샘플을 유지한다. 최소 포함 케이스는 승인, 전체 취소, 부분 취소, 할부, 해외 승인, 동일 금액 연속 결제, 중복 수신, 다중 키워드, 제외 키워드, 금액·시각 누락, 카드사 형식 변경이다.

### 베타 품질 게이트

- 명확한 SMS 자동 반영 정밀도: 98% 이상
- 자동 반영 후 사용자가 제외·이동한 비율: 2% 이하
- 확인 필요 거래 비율: 5% 이하
- 중복 반영: 0건
- 중대 오류(취소를 승인으로 반영, 다른 카드에 자동 반영): 발견 즉시 자동 반영 중단 후 수정

## 10. 보안·개인정보·백업

- 로컬 DB는 Android Keystore 기반 키로 암호화한다.
- SMS 원문, 주민등록번호, 카드 번호, CVC, 금융기관 로그인 정보는 저장하지 않는다.
- 상점명·금액·fingerprint도 개인 데이터로 취급하며, 외부 전송·광고·분석 목적 사용을 금지한다.
- 지원 진단 로그에는 거래 데이터와 매칭 키워드를 기록하지 않는다.
- `내 데이터`에서 로컬 데이터 전체 삭제와 내보내기 기능을 제공한다.
- P1 백업은 암호화 파일만 제공한다. 복구 전 카드 수·거래 수·기간을 표시하고 병합/교체를 선택하게 한다.
- 암호화 백업의 비밀번호를 잃어버리면 복구할 수 없음을 명시한다. 기기 초기화·앱 삭제 전에는 백업을 권장한다.

## 11. 수용 기준

1. 사용자는 카드 1개를 1분 이내에 등록한다.
2. 명확한 신규 승인 SMS는 5초 내 자동 반영한다.
3. 다중 매칭·파싱 실패·신뢰도 미달 거래는 어떤 합계에도 자동 반영하지 않는다.
4. 사용자는 각 거래의 목표 추적·구매 추적 한도 포함 여부를 독립적으로 수정할 수 있다.
5. 수신·재시작·P1 재스캔 후에도 같은 fingerprint 거래는 한 번만 반영된다.
6. SMS 원문은 DB, 백업, 로그에 없다.
7. 권한 해제 직후 새 SMS 접근을 중단한다.
8. 카드별 주기가 다를 때 각 카드의 합계와 남은 일수가 독립적으로 계산된다.
9. ‘개인 추적값’과 ‘카드사 공식 실적이 아님’ 안내가 홈과 거래 상세에 표시된다.

## 12. 출시 순서

1. **정책 사전 검증:** 권한 선언서, 데이터 흐름도, 개인정보처리방침, 온보딩 고지, 심사용 절차를 완성한다.
2. **내부 알파:** 파서 코퍼스·중복·취소·주기 계산·로컬 암호화를 검증한다.
3. **제한 베타:** SMS 동의 사용자만 자동 집계를 사용하고 품질 게이트를 측정한다.
4. **공개 출시:** 정책 승인과 베타 품질 기준을 충족한 뒤 활성화한다.

## 13. 출시 전 최종 결정

- P0에서 실제로 필요한 Android SMS 권한 조합과 Android 버전별 동작
- 개인 구매 추적 한도의 기본값 및 사용자별 복수 한도 지원 여부
- 실적 추적 포함 기본값과 카드사별 제외 규칙을 P1에 제공할지 여부
- P1 백업의 비밀번호 UX 및 복구 책임 고지
- 정책 심사 거절 시 수동·제한 모드 배포를 계속할지 여부

### 정책 근거

- Google Play는 SMS 권한을 민감 권한으로 분류하고, ‘SMS 기반 자금 관리(예: 예산 추적·관리)’를 예외 사용 사례로 제시한다. [SMS 또는 통화 기록 권한 그룹 사용](https://support.google.com/googleplay/android-developer/answer/10208820?hl=ko)
- 허용된 핵심 기능 목적의 최소한의 데이터 접근, 명확한 고지·동의와 목적 외 사용 금지가 요구된다. [민감한 정보에 액세스하는 권한 및 API](https://support.google.com/googleplay/android-developer/answer/16558241)
